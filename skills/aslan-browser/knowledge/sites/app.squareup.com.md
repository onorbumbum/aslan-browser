# app.squareup.com (Square Dashboard)

- Built from `market-*` web components with nested shadow roots. `aslan tree` shows buttons but not inputs, dropdown options or Save; reach them by walking `el.shadowRoot` recursively in `aslan eval`, then set values with the native `HTMLInputElement` value setter plus bubbling, composed `input`/`change` events.
- When walking a component, include the host's own `shadowRoot` (`all(dp.shadowRoot)`); `dp.querySelectorAll` alone misses its internals.
- Mark an invoice paid: `/dashboard/invoices/<invoice id>` > "Mark as paid" > Payment method combobox (Cash, Check, Square Point of Sale, Other) > optional Personal note > click the `MARKET-BUTTON` whose text is "Save". The API (`invoices-pay`) returns 403 for invoices on dashboard-owned orders, so use this.
- Mark as paid defaults "Send email receipt to customer" on. When email is not authorized, switch it off before Save and read back the shadow-root input's `checked` state after the UI settles. Personal note has a 100-character limit.
- Recurring series list: `/dashboard/invoices/series`; rows show "Ended on <date>" for series that ran their term. Clicking a row opens a side panel with Repeats/Ended details.
- End series from its detail blade's `End recurring series` button. The confirmation is `[data-testid="invoices-end-recurring-series-modal-confirm"]` and explicitly states that future invoices stop but outstanding invoices still apply. Confirm once, reload, verify `Ended on <date>` and recheck the series-filtered invoice list. A future placeholder invoice disappears; already-issued overdue invoices remain collectible.
- New series: `/dashboard/invoices/series/new`. Customer and "Add an item" are searchable inputs; pick results from `MARKET-ROW` elements. Start dropdown has presets plus a `MARKET-DATE-PICKER` (Next month = `MARKET-BUTTON[aria-label="Next month"]`; days are `MARKET-DATE-PICKER-DATE[day="13"]`). With a future start date the top-right button reads "Schedule" instead of "Send".
- Series recipient snapshots can retain the old customer name/email after an API customer update. In the series editor, View details reads the current linked profile; Save refreshes the editor's recipient, but also writes the customer and can normalize an unset address country to US. Do not treat that Save as read-only.
- Removing and re-selecting the same customer refreshes the recipient without a customer Save, but clears the editor's payment-method selection. Restore the exact original stored-card ID in Payment options before saving, then compare all form values and settings text against the baseline. Select the exact customer row by its label and use the pointer/mouse event sequence if a plain `.click()` selects the wrong search option. Never save the resulting New customer form.
- Series editor Update can open "Update series and override previous changes?" warning that prior scheduled-invoice changes, including send dates and line items, will be lost. The initial Update is not the final save when this dialog appears. Cancel and seek approval if scheduled-invoice overwrite is outside scope.
- Sign-in requires Onur's password and SMS code; let him log in and never close or navigate his tab meanwhile.
- Existing invoice detail > Remind opens a separate Send reminder dialog. It names the email recipient, has an optional Reminder message textarea, and a final Send button. Opening Remind does not send; do not click Send without scoped approval. This dialog does not show the generated email subject, body, footer or attachment rendering, so it is not a complete rendered-email privacy check.
